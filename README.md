Sprint Planning: Managing Competing Priorities

One-month sprint plan managing 10 developers across three hospital clients with limited capacity.

Overview
Scenario: 10 developers (7.5 effective FTE) | 3 hospital clients | 1 month sprint
Challenge: Strategic prioritization under resource constraints

Prioritization Rationale
Hospital C (50%) - Last chance before client closes. Features benefit future product roadmap.
Hospital B (35%) - New high-value client. Scope reduced to Phase 1 (core features only).
Hospital A (15%) - Established relationship. Critical fixes only, deferring enhancements.
Sprint Timeline
Week 1: Foundation & requirements
Week 2: Core development
Week 3: Integration & refinement
Week 4: Testing, deployment (20% buffer)
Key Trade-offs

Hospital A: Delivering critical fixes only, not full overhaul
Hospital B: Core HR features only (no payroll/recruitment yet)
Hospital C: Full delivery—no deferrals

Success Metrics

Hospital C: 100% scope delivered
Hospital B: Phase 1 live and usable
Hospital A: Top 3 critical issues resolved
Team: <45 hours/week, >7/10 satisfaction
